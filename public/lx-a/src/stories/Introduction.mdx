# My Lexus — Design System

A working catalogue of every component, pattern and foundation used in the
authenticated **My Lexus** experience. Built for designers, developers and
content people to share a single source of truth.

This Storybook is organised in concentric circles — from the smallest design
decisions outward:

- **Foundations** — colour, typography, spacing, radii, shadows, motion,
  tracking and icons. The tokens that everything else uses.
- **Primitives** — single-purpose, reusable inputs and surfaces. Buttons,
  TextField, Checkbox, Radio, DataTable, DatePicker, Skeleton.
- **Composition** — composed UI elements that combine primitives into a
  recognisable Lexus pattern. BenefitCard, VehiclePanel, Hero, TodayModule.
- **Patterns** — repeatable behavioural patterns. Flyout, Confirmation,
  StepIndicator, Notifications popover.
- **Visualisation** — data displays. ServiceTimeline, PointsSparkline.
- **Pages** — full screens composed from everything above so reviewers can
  see real composition.
- **Authentication** — the unauthenticated screens.

## How this Storybook is structured

Every component story carries:

- A short **purpose** statement — what this component does and when to use it.
- A **default** story showing the canonical use case.
- One or more **variant** stories covering states, sizes and edge cases.
- **Accessibility** notes — keyboard interactions, ARIA roles, focus
  management and contrast considerations.
- **Specs** — sizes, paddings and token references (e.g. `--space-4`).
- **Interaction** examples for components that respond to user input.
- **Controls** for the live preview, so designers can experiment with props
  without writing code.

## Conventions

- All visual values are token-driven. If you see a literal in a story, it is
  a one-off override and should be questioned in code review.
- Themes are switchable from the toolbar (☀️ Light / 🌙 Dark / Auto). Components
  must read in both themes; light theme uses the warm smoke palette, dark uses
  Lexus deepblue.
- Stories run inside the real `FlyoutProvider`, so flyout-launching components
  work as they do in product.
- Accessibility is checked automatically by the `a11y` addon on every story.
  Failing rules will appear in the Accessibility panel.

## Getting started

- Browse the sidebar to find a component by name.
- Use the **Docs** tab on any story for prose + spec.
- Use the **Canvas** tab to interact with the live component and tweak props.
- The **Accessibility** panel reports WCAG-style violations and warnings.
- The **Interactions** panel lets you replay scripted interactions.

If a component is missing from this catalogue, please add a story for it.
